# 上线部署指南

> 适用于：把后端部署到 Ubuntu 服务器（systemd + Nginx 反向代理 + 阿里云免费 SSL 证书），并把小程序发布上线。
> 更新时间：2026-10-08

## 0. 总览

### 0.1 部署后的结构

```
小程序 ──HTTPS / WSS──▶ Nginx（443，阿里云 SSL 证书）
                          │  /api/*    → http://127.0.0.1:5080
                          │  /hubs/*   → http://127.0.0.1:5080（WebSocket）
                          ▼
                   FamilyMenu.Api（systemd 服务，只监听本机 5080）
                          │
                          ▼
                   SQLite：/var/lib/family-menu/family.db
```

后端只监听 `127.0.0.1`，外网只能经过 Nginx 访问，5080 端口不对外开放。

### 0.2 文中的占位符

下面的命令和配置里用到这些占位符，执行前全部替换成自己的值：

| 占位符 | 含义 |
|---|---|
| `menu.example.com` | 给后端用的域名（建议单独用一个子域名） |
| `<服务器IP>` | 服务器公网 IP |
| `ubuntu` | 登录服务器用的 SSH 用户名（阿里云 Ubuntu 镜像默认是 `root` 或 `ecs-user`，以实际为准） |
| `wx你的AppId` / `你的AppSecret` | 微信公众平台「开发管理 → 开发设置」中的 AppID 和 AppSecret |

### 0.3 上线顺序

1. 准备域名、完成备案、配置 DNS 解析（第 1 节）
2. 服务器安装运行环境（第 2 节）
3. 在本机发布后端并上传到服务器（第 3 节）
4. 配置 systemd 服务（第 4 节）
5. 申请阿里云 SSL 证书，配置 Nginx（第 5、6 节）
6. 验证接口和 WebSocket（第 7 节）
7. 配置小程序后台、修改小程序配置、上传发布（第 9 节）

## 1. 准备域名和备案

1. **ICP 备案**：
   - 服务器在中国大陆（例如阿里云华东、华北地域）时，域名必须先在阿里云完成 ICP 备案，否则 80/443 端口的访问会被拦截。
   - 微信小程序的「服务器域名」也要求是已备案的域名。
   - 备案一般需要 1～3 周，建议最先开始办。
2. **DNS 解析**：在域名解析控制台添加一条 A 记录：

   | 记录类型 | 主机记录 | 记录值 |
   |---|---|---|
   | A | `menu` | `<服务器IP>` |

   验证：本机执行 `ping menu.example.com`，返回的 IP 是服务器 IP 即生效。
3. **安全组**：阿里云 ECS 控制台 → 安全组 → 入方向，放行 TCP `22`、`80`、`443`。**不要**放行 `5080`。

## 2. 服务器安装运行环境

以下命令在服务器上执行（Ubuntu 22.04 / 24.04 / 26.04 均适用）。

### 2.1 系统更新和基础工具

```bash
sudo apt-get update && sudo apt-get upgrade -y
sudo apt-get install -y nginx sqlite3 tzdata curl
```

- `tzdata`：后端用 `Asia/Shanghai` 计算「今天」，缺少时区数据会启动失败。Ubuntu 一般已自带，装一下没坏处。
- `sqlite3`：用于备份数据库（第 8 节），运行后端本身不需要。

### 2.2 安装 ASP.NET Core 10 运行时

服务器只需要运行时，不需要 SDK（程序在本机编译好再上传）。

```bash
sudo apt-get install -y aspnetcore-runtime-10.0
```

如果提示「无法定位软件包 aspnetcore-runtime-10.0」，说明当前 Ubuntu 版本的官方源里还没有 .NET 10，先添加 .NET backports 源再装：

```bash
sudo add-apt-repository -y ppa:dotnet/backports
sudo apt-get update
sudo apt-get install -y aspnetcore-runtime-10.0
```

验证：

```bash
dotnet --list-runtimes
```

输出中有 `Microsoft.AspNetCore.App 10.0.x` 即可。再执行 `which dotnet` 记下路径（通常是 `/usr/bin/dotnet`），第 4 节要用。

### 2.3 创建运行用户和目录

```bash
# 专门用来运行后端的系统用户，不能登录
sudo useradd --system --no-create-home --shell /usr/sbin/nologin familymenu

# 程序目录、数据目录、配置目录、备份目录
sudo mkdir -p /opt/family-menu/app /var/lib/family-menu /etc/family-menu /var/backups/family-menu
sudo chown familymenu:familymenu /var/lib/family-menu
```

| 目录 | 用途 |
|---|---|
| `/opt/family-menu/app` | 后端程序文件，每次更新整体替换 |
| `/var/lib/family-menu` | SQLite 数据库，**更新程序时不动这里** |
| `/etc/family-menu` | 环境变量文件（含密钥） |
| `/var/backups/family-menu` | 数据库备份 |

### 2.4 防火墙（可选）

如果启用了 ufw，先放行 SSH 再启用，避免把自己锁在外面：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status
```

## 3. 发布后端并上传

以下命令在**本机 Windows**（PowerShell）上、仓库根目录执行。

### 3.1 编译发布

先在服务器上执行 `uname -m` 确认 CPU 架构：`x86_64` 用 `linux-x64`，`aarch64`（例如阿里云倚天实例）用 `linux-arm64`。

```powershell
dotnet publish backend/FamilyMenu.Api -c Release -r linux-x64 --self-contained false -o artifacts/api
```

- 输出目录 `artifacts/` 已在 `.gitignore` 中，不会被提交。
- `appsettings.Development.json` 也会被一起发布，但 Production 环境不会加载它，不影响。

### 3.2 打包上传

```powershell
tar -czf artifacts/family-menu-api.tar.gz -C artifacts/api .
scp artifacts/family-menu-api.tar.gz ubuntu@<服务器IP>:/tmp/
```

Windows 10 及以上自带 `tar` 和 `scp`，不需要额外安装。

### 3.3 解压到程序目录

在服务器上执行：

```bash
sudo tar -xzf /tmp/family-menu-api.tar.gz -C /opt/family-menu/app
ls /opt/family-menu/app/FamilyMenu.Api.dll
```

## 4. 配置 systemd 服务

### 4.1 生成 JWT 密钥

```bash
openssl rand -hex 32
```

把输出的 64 位字符串复制下来，下一步填进 `Jwt__Secret`。这个密钥一旦更换，所有人都需要重新登录。

### 4.2 写环境变量文件

```bash
sudo nano /etc/family-menu/family-menu.env
```

内容如下（替换占位符）：

```ini
ASPNETCORE_ENVIRONMENT=Production
ASPNETCORE_URLS=http://127.0.0.1:5080

ConnectionStrings__Default="Data Source=/var/lib/family-menu/family.db"

Jwt__Secret=上一步生成的64位字符串

Wechat__AppId=wx你的AppId
Wechat__AppSecret=你的AppSecret

Cors__AllowedOrigins__0=https://menu.example.com
ForwardedHeaders__KnownProxies__0=127.0.0.1
```

| 变量 | 说明 |
|---|---|
| `ASPNETCORE_URLS` | 只监听本机，外网必须经过 Nginx |
| `ConnectionStrings__Default` | 数据库放在独立的数据目录，更新程序不会误删。值里有空格，要加引号 |
| `Wechat__AppId` | 必须和小程序 `project.config.json` 里的 `appid` 一致，否则微信登录会报 `invalid code` |
| `Cors__AllowedOrigins__0` | 生产环境要求至少配置一个 HTTPS origin。小程序请求不受 CORS 限制，填后端域名即可 |
| `ForwardedHeaders__KnownProxies__0` | 只信任本机 Nginx 转发的 `X-Forwarded-*` 头，用于识别 HTTPS 和真实客户端 IP（登录限流按 IP 计算） |

不要设置 `Wechat__AllowDevelopmentOpenId`，Production 环境开启它后端会拒绝启动。

收紧文件权限（里面有 AppSecret 和 JWT 密钥）：

```bash
sudo chmod 600 /etc/family-menu/family-menu.env
sudo chown root:root /etc/family-menu/family-menu.env
```

### 4.3 创建服务

```bash
sudo nano /etc/systemd/system/family-menu.service
```

```ini
[Unit]
Description=Family Menu API
After=network.target

[Service]
Type=simple
User=familymenu
Group=familymenu
WorkingDirectory=/opt/family-menu/app
ExecStart=/usr/bin/dotnet /opt/family-menu/app/FamilyMenu.Api.dll
EnvironmentFile=/etc/family-menu/family-menu.env
Environment=DOTNET_NOLOGO=1
Restart=always
RestartSec=5
KillSignal=SIGINT
TimeoutStopSec=30
SyslogIdentifier=family-menu

# 基本加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

`ExecStart` 中的 `dotnet` 路径以 2.2 节 `which dotnet` 的结果为准。

### 4.4 启动并检查

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now family-menu
sudo systemctl status family-menu
```

看到 `active (running)` 后验证：

```bash
curl http://127.0.0.1:5080/health
```

返回 `Healthy` 即成功。首次启动会自动执行数据库迁移，在 `/var/lib/family-menu/` 下创建 `family.db`。

查看日志：

```bash
sudo journalctl -u family-menu -n 100 --no-pager
```

启动失败时日志里会写明原因，常见的有：

| 日志内容 | 处理 |
|---|---|
| `Jwt:Secret 未配置或不安全` | 环境变量文件里 `Jwt__Secret` 缺失或不足 32 位 |
| `生产环境必须配置 Wechat:AppId 和 Wechat:AppSecret` | 补全 `Wechat__AppId` / `Wechat__AppSecret` |
| `生产环境必须配置至少一个 Cors:AllowedOrigins` | 补全 `Cors__AllowedOrigins__0`，必须是 `https://` 开头且不带路径 |
| `Family:TimeZone 不是有效的时区 ID` | `sudo apt-get install -y tzdata` |
| `unable to open database file` | 数据目录权限不对：`sudo chown familymenu:familymenu /var/lib/family-menu` |

## 5. 申请阿里云免费 SSL 证书

1. 登录 [阿里云控制台](https://www.aliyun.com)，搜索进入「数字证书管理服务」→「SSL 证书管理」。
2. 选择「个人测试证书」（即免费证书），领取免费额度后点击「创建证书」。
3. 填写证书绑定域名 `menu.example.com`，域名验证方式选「DNS 验证」：
   - 域名解析在阿里云时，勾选自动添加验证记录即可；
   - 解析在其他服务商时，按页面提示手动添加一条 TXT 记录。
4. 提交审核，通常几分钟到几十分钟签发。
5. 签发后点击「下载」，服务器类型选择 **Nginx**，得到一个压缩包，解压后有两个文件：
   - `menu.example.com.pem`：证书（已包含证书链）
   - `menu.example.com.key`：私钥
6. 上传到服务器：

   ```powershell
   scp menu.example.com.pem menu.example.com.key ubuntu@<服务器IP>:/tmp/
   ```

   ```bash
   sudo mkdir -p /etc/nginx/ssl
   sudo mv /tmp/menu.example.com.pem /tmp/menu.example.com.key /etc/nginx/ssl/
   sudo chmod 600 /etc/nginx/ssl/menu.example.com.key
   ```

> **注意有效期**：阿里云免费证书目前有效期只有 3 个月（以控制台显示为准），到期前需要重新申请并替换文件，见 8.3 节。建议在日历里设一个到期前两周的提醒。证书过期后小程序会直接无法联网。

## 6. 配置 Nginx 反向代理

### 6.1 站点配置

```bash
sudo nano /etc/nginx/sites-available/family-menu
```

```nginx
# WebSocket 升级：有 Upgrade 头时转发 upgrade，否则正常关闭连接
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

# HTTP 全部跳转到 HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name menu.example.com;

    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name menu.example.com;

    ssl_certificate     /etc/nginx/ssl/menu.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/menu.example.com.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 1d;

    # 接口只收发 JSON，没有文件上传
    client_max_body_size 1m;

    # SignalR 实时连接（WebSocket）
    location /hubs/ {
        proxy_pass         http://127.0.0.1:5080;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade           $http_upgrade;
        proxy_set_header   Connection        $connection_upgrade;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        # 长连接不能被 Nginx 默认的 60 秒超时断开
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
        proxy_buffering    off;

        # 连接地址里带着 access_token，不写访问日志，避免 token 落盘
        access_log off;
    }

    # 普通接口和健康检查
    location / {
        proxy_pass         http://127.0.0.1:5080;
        proxy_http_version 1.1;
        proxy_set_header   Connection        "";
        proxy_set_header   Host              $host;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
```

几个容易踩的坑：

- **每个 `location` 都要完整写一遍 `proxy_set_header`**。Nginx 的规则是：只要 `location` 里出现了任何一条 `proxy_set_header`，就不再继承外层的设置。
- `X-Forwarded-Proto` 必须传，后端在 Production 环境开启了 HTTPS 跳转，靠它判断请求原本就是 HTTPS，否则会出现重定向异常。
- `proxy_pass` 写 `127.0.0.1` 而不是 `localhost`，避免解析到 IPv6 的 `::1`，和 `KnownProxies` 对不上。

### 6.2 启用站点

```bash
sudo ln -s /etc/nginx/sites-available/family-menu /etc/nginx/sites-enabled/family-menu
sudo rm -f /etc/nginx/sites-enabled/default   # 移除默认欢迎页（可选）
sudo nginx -t
sudo systemctl reload nginx
```

`nginx -t` 显示 `syntax is ok` 和 `test is successful` 后再 reload。

## 7. 验证

在本机或服务器上执行：

```bash
# 1. HTTP 自动跳转 HTTPS，预期 301
curl -I http://menu.example.com/health

# 2. HTTPS 接口，预期输出 Healthy
curl https://menu.example.com/health

# 3. 未登录访问接口，预期 401（说明请求已经到达后端）
curl -i https://menu.example.com/api/auth/me

# 4. WebSocket 路由，预期 401 Unauthorized（没带 token 被后端拒绝）；如果是 404 或 502 说明 /hubs/ 代理没配好
curl -i --http1.1 -N \
  -H "Connection: Upgrade" -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" -H "Sec-WebSocket-Key: SGVsbG8sIHdvcmxkIQ==" \
  https://menu.example.com/hubs/family
```

证书检查：浏览器打开 `https://menu.example.com/health`，地址栏显示安全锁，证书颁发对象是 `menu.example.com`、在有效期内。

## 8. 日常运维

### 8.1 更新后端

本机按第 3.1、3.2 节重新发布并上传 `family-menu-api.tar.gz`，然后在服务器上：

```bash
# 停服务
sudo systemctl stop family-menu

# 备份数据库（停服后再备份，数据最完整）
sudo cp -a /var/lib/family-menu/. /var/backups/family-menu/before-update-$(date +%F-%H%M)/

# 保留旧版本程序，出问题可以回滚
sudo rm -rf /opt/family-menu/app.prev
sudo mv /opt/family-menu/app /opt/family-menu/app.prev
sudo mkdir -p /opt/family-menu/app
sudo tar -xzf /tmp/family-menu-api.tar.gz -C /opt/family-menu/app

# 启动并看日志，新的数据库迁移会在启动时自动执行
sudo systemctl start family-menu
sudo journalctl -u family-menu -n 50 --no-pager
curl http://127.0.0.1:5080/health
```

回滚：停服务 → 把 `app.prev` 改回 `app` → 如果新版本执行过数据库迁移，把备份的数据库文件拷回 `/var/lib/family-menu/`（注意保持 `familymenu` 属主）→ 启动。

### 8.2 每日自动备份数据库

`sqlite3 .backup` 可以在服务运行时安全地做一致性备份：

```bash
sudo tee /etc/cron.daily/family-menu-backup > /dev/null <<'EOF'
#!/bin/sh
set -e
BACKUP_DIR=/var/backups/family-menu
sqlite3 /var/lib/family-menu/family.db ".backup '$BACKUP_DIR/family-$(date +%F).db'"
# 只保留最近 30 天
find "$BACKUP_DIR" -maxdepth 1 -name 'family-*.db' -mtime +30 -delete
EOF
sudo chmod +x /etc/cron.daily/family-menu-backup

# 手动跑一次确认能用
sudo /etc/cron.daily/family-menu-backup
ls -lh /var/backups/family-menu/
```

`/etc/cron.daily/` 下的文件名不能带 `.`，否则不会被执行。备份最好再定期拷一份到服务器以外的地方（例如本机或阿里云 OSS）。

### 8.3 更换到期的证书

在阿里云重新申请证书（第 5 节），下载 Nginx 格式，上传覆盖 `/etc/nginx/ssl/` 下的同名文件，然后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

不需要重启后端。想彻底免去手动续期，可以改用 `acme.sh` 或 `certbot` 申请 Let's Encrypt 证书并自动续期，Nginx 配置只需改两行证书路径。

### 8.4 常用命令

| 用途 | 命令 |
|---|---|
| 查看服务状态 | `sudo systemctl status family-menu` |
| 实时看日志 | `sudo journalctl -u family-menu -f` |
| 重启后端 | `sudo systemctl restart family-menu` |
| 修改环境变量后生效 | `sudo systemctl restart family-menu` |
| Nginx 错误日志 | `sudo tail -f /var/log/nginx/error.log` |

## 9. 小程序发布

### 9.1 微信公众平台配置

登录 [微信公众平台](https://mp.weixin.qq.com)：

1. **核对 AppID / AppSecret**：「开发管理 → 开发设置」。
   - AppID 要和 `miniprogram/project.config.json` 里的 `appid` 一致。
   - AppSecret 只在生成时显示一次，丢了只能重置；重置后要同步修改服务器的 `Wechat__AppSecret` 并重启后端。
2. **配置服务器域名**：「开发管理 → 开发设置 → 服务器域名」→ 修改：

   | 类型 | 填写 |
   |---|---|
   | request 合法域名 | `https://menu.example.com` |
   | socket 合法域名 | `wss://menu.example.com` |

   - 小程序没有上传和下载文件，uploadFile、downloadFile 合法域名不用填。
   - 域名每月修改次数有限，填之前确认无误。
   - 实时同步走 SignalR，地址由 `API_BASE_URL` 自动推导为 `wss://menu.example.com/hubs/family`，所以 socket 合法域名必须配。
3. **用户隐私保护指引**：「设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引」。
   家庭页用了 `<input type="nickname">` 让用户填写微信昵称，需要在指引中声明收集「昵称」，用途可以写「在家庭成员列表中展示，便于家人识别」。不配置的话，昵称输入框选不了微信昵称，审核也可能被驳回。
4. **成员管理**：「成员管理」中把家人的微信号添加为「体验成员」，上线前就能用体验版试用。

### 9.2 修改小程序配置

编辑 [`miniprogram/miniprogram/services/config.ts`](../miniprogram/miniprogram/services/config.ts)：

```ts
export const API_BASE_URL = 'https://menu.example.com/api'
export const LOGIN_MODE: 'development' | 'wechat' = 'wechat'
```

- `LOGIN_MODE` 必须改成 `'wechat'`。生产后端不接受测试身份，`development` 模式在正式环境无法登录。
- 改完后本地联调要连本机后端时，记得改回 `development` 和局域网地址（或者另建一个分支专门放上线配置）。

### 9.3 构建并真机验证

1. 在 `miniprogram/` 下执行 `npm install`，开发者工具中「工具 → 构建 npm」。
   `project.config.json` 已配置了 `beforeCompile` / `beforePreview` / `beforeUpload` 钩子，会自动执行 SignalR 适配脚本。
2. 「详情 → 本地设置」中**取消勾选**「不校验合法域名」，确保开发者工具按正式规则校验域名。
3. 「详情 → 项目配置」中确认「request 合法域名」「socket 合法域名」已经出现刚才配置的域名（没出现就点刷新）。
4. 点击「预览」，用手机扫码。手机上如果之前打开过「开发调试」，先关掉（右上角「···」→「开发调试」→「关闭调试」），否则域名校验会被跳过，测不出问题。
5. 验证清单：
   - [ ] 微信登录成功，首次进入能设置昵称
   - [ ] 创建家庭、复制邀请码
   - [ ] 第二个微信号（需是体验成员或开发者）用邀请码加入
   - [ ] 一边新增菜品 / 点菜，另一边无需刷新自动更新（验证 WSS 实时连接）
   - [ ] 切到后台 30 秒再回来，数据能自动刷新

### 9.4 上传代码

1. 开发者工具右上角「上传」，填写版本号（例如 `1.0.0`）和备注。
2. 上传成功后，在公众平台「管理 → 版本管理 → 开发版本」能看到这个版本。
3. 点击「选为体验版」，体验成员扫描体验版二维码即可使用。

> 如果只是自己家里人用，停在**体验版**也完全可以：把家人加为体验成员就能长期使用，不需要审核和备案。下面的步骤是正式发布才需要的。

### 9.5 小程序备案

2023 年 9 月起，小程序必须完成备案才能提交审核上线。

1. 公众平台首页「小程序备案」，按要求填写主体信息（个人主体需要身份证）和小程序信息。
2. 提交后先由微信初审，再提交到管局审核，期间会收到管局的短信核验，需要按短信提示在规定时间内完成。
3. 整个过程一般需要 1～2 周。

这里的小程序备案和第 1 节的域名 ICP 备案是两件事，都要办。

### 9.6 提交审核和发布

1. 先完善「设置 → 基本设置」：小程序名称、头像、简介、服务类目（选和「家庭点餐 / 菜单管理」相符的类目，以后台可选项为准）。
2. 「版本管理」→ 开发版本「提交审核」。审核说明可以写：
   > 家庭共享菜单与点餐工具。微信登录后，在「家庭」页创建家庭即可体验全部功能；邀请码用于邀请家人加入同一个家庭。
3. 审核通过后，在「审核版本」中点击「发布」，小程序正式上线。

### 9.7 后续更新

- **先更新后端，再发小程序**。新版小程序依赖的接口要先在服务器上可用；旧版小程序在用户手机上还会继续跑一段时间，后端改动要尽量兼容旧接口。
- 只改后端：按 8.1 节更新即可，不用重新发小程序。
- 改了小程序：重新上传 → 提交审核 → 发布（体验版只需上传后重新选为体验版）。

## 10. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 浏览器访问域名提示无法访问 / 连接被重置 | 域名没备案（大陆服务器）、DNS 未生效，或安全组 / ufw 没放行 80、443 |
| `502 Bad Gateway` | 后端没在运行或端口不对：`systemctl status family-menu`、`curl http://127.0.0.1:5080/health` |
| 小程序提示「不在以下 request 合法域名列表中」 | 9.1 节的服务器域名没配，或开发者工具里没刷新项目配置 |
| 接口正常但实时不同步 | socket 合法域名没配 `wss://`；或 Nginx `/hubs/` 缺少 `Upgrade` / `Connection` 头，用第 7 节第 4 条命令检查 |
| 实时连接每隔约 1 分钟断一次 | `/hubs/` 的 `proxy_read_timeout` 没加大 |
| 微信登录失败，日志中有「微信错误码：40029」 | code 无效：服务器 `Wechat__AppId` 和小程序 `appid` 不一致，或 code 已被使用过 |
| 微信登录失败，日志中有「微信错误码：40125」 | AppSecret 错误或已被重置，更新环境变量后重启后端 |
| 微信登录失败，日志中有「调用微信登录接口超时 / 失败」 | 服务器访问不了 `api.weixin.qq.com`，检查出网和 DNS |
| 登录返回 `429` | 同一 IP 每分钟登录超过 20 次被限流，稍等一分钟 |
| 所有用户突然都需要重新登录 | `Jwt__Secret` 被修改过，属于正常现象 |
| 昵称输入框无法选择微信昵称 | 没配置用户隐私保护指引（9.1 节第 3 步） |
| 「今天」的点餐日期不对 | 服务器缺 `tzdata`，或改过 `Family__TimeZone`；与服务器系统时区无关 |
| 小程序突然全部请求失败 | 检查 SSL 证书是否过期（第 5 节注意事项） |
