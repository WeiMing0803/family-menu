# 双机联调测试指南

> 适用于：用两台手机模拟两位家庭成员，验证家庭加入、菜品和点餐的实时同步。
> 更新时间：2026-09-30

## 1. 为什么两台手机登录后是同一个人

小程序默认使用 `development` 登录模式（见 `miniprogram/miniprogram/services/config.ts` 的 `LOGIN_MODE`）。这个模式不走微信授权，而是把一个固定的 `openId` 发给后端，由后端的 Development 环境直接认作用户身份。

早期版本里，本地没有登录信息时会**静默**使用默认身份 `local-user-a` 自动登录，所以无论哪台手机扫码，登录的都是同一个用户，看到的也是同一个家庭，无法测试两人之间的实时同步。

现在的处理：

- Development 模式下不再自动登录，没有选择过身份的设备会进入登录页。
- 登录页可以选择「测试用户 A」（`local-user-a`）或「测试用户 B」（`local-user-b`），选择会保存在本机。
- 家庭页底部的按钮在联调模式下显示为「切换测试身份」，可以随时回到登录页换身份。

测试身份列表定义在 `config.ts` 的 `DEVELOPMENT_IDENTITIES`，需要更多身份时直接在这里追加。

## 2. 准备工作

1. **启动后端**：在 `backend/FamilyMenu.Api` 下执行 `dotnet run`，后端监听 `http://0.0.0.0:5080`（Development 环境）。
2. **确认局域网地址**：电脑和两台手机连接同一个 Wi-Fi。`config.ts` 中的 `API_BASE_URL` 要写电脑的局域网 IP（当前为 `http://192.168.1.95:5080/api`）。电脑 IP 变化后需要同步修改。
3. **放行防火墙端口**：Windows 防火墙默认会拦截手机访问 5080 端口，用管理员 PowerShell 执行一次：

   ```powershell
   New-NetFirewallRule -DisplayName "FamilyMenu API 5080" -Direction Inbound -Protocol TCP -LocalPort 5080 -Action Allow
   ```

   验证方法：用手机浏览器打开 `http://192.168.1.95:5080/health`，能看到 `Healthy` 即网络已通。
4. **添加项目成员**：第二台手机上的微信号必须在 [微信公众平台](https://mp.weixin.qq.com) →「成员管理」中被添加为「开发者」或「体验成员」，否则扫描预览二维码会提示无权限。

## 3. 测试步骤

1. 在微信开发者工具中点击「预览」，两台手机分别扫码打开小程序。
2. **两台手机都要**打开调试模式：小程序右上角「···」→「开发调试」→「打开调试」，然后关闭并重新打开小程序。
   打开调试后，手机才会允许访问 `http://局域网IP` 这类非 HTTPS、未配置合法域名的地址。
3. 选择身份：手机 1 选「测试用户 A」，手机 2 选「测试用户 B」，点击「以测试身份登录」。
   如果某台手机之前已经自动登录成 A，先进入「家庭」页 →「切换测试身份」，再选择 B。
4. 建立家庭：
   - 手机 A：「家庭」页 → 创建家庭 → 复制邀请码。
   - 手机 B：「家庭」页 → 输入邀请码 → 加入家庭。
   - **预期**：手机 A 的成员列表无需刷新，自动出现「测试用户 B」。
5. 验证实时同步（每一步都在另一台手机上观察，无需手动刷新）：

   | 操作手机 | 操作 | 另一台手机的预期 |
   |---|---|---|
   | A | 菜单页新增一道菜 | B 的菜单页出现这道菜 |
   | B | 选菜后「加入今日点餐」 | A 的今日页出现这道菜，菜单页按钮变为「已点」 |
   | A | 今日页点击菜名 → 已做完 / 不吃了 / 添加备注 | B 的今日页状态和备注同步变化 |
   | B | 今日页删除一道菜 | A 的今日页该菜消失 |
   | A | 清空今日点餐 | B 的今日页清空，历史页出现该记录 |
   | B | 家庭页 → 退出家庭 | A 的成员列表只剩自己 |

6. 断线重连：把其中一台手机切到后台 30 秒再切回，或短暂关闭 Wi-Fi 再打开，另一台手机做一次修改，确认切回的手机能自动刷新到最新数据。

## 4. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 两台手机显示同一个人 | 本机保存了旧的登录信息。进入「家庭」页 →「切换测试身份」重新选择。 |
| 手机提示「网络请求失败」 | 依次检查：手机和电脑是否同一 Wi-Fi；手机浏览器能否打开 `/health`；防火墙规则是否添加；是否已「打开调试」。 |
| 扫码提示无权限 | 该微信号未被添加为项目成员，见第 2 节第 4 步。 |
| 数据能加载，但对方的修改不会自动出现 | SignalR 连接未建立。打开调试后在 vConsole 中查看是否有 WebSocket 报错；确认后端 `/hubs/family` 可访问；加入家庭后回到任意页面会自动重连。 |
| 登录页提示「请先选择测试身份」 | 正常现象，选择一个身份后再登录即可。 |

## 5. 使用真实微信账号测试（上线前）

开发模式适合快速联调。上线前需要用真实微信登录再验证一遍，此时每个微信号天然对应不同的 `openid`，不需要选择身份：

1. 把 `config.ts` 中的 `LOGIN_MODE` 改为 `'wechat'`。
2. 在后端配置小程序的 AppId 和 AppSecret。不要写进仓库，在 `backend/FamilyMenu.Api` 下使用 User Secrets（第一次使用需先 `init`）：

   ```powershell
   dotnet user-secrets init
   dotnet user-secrets set "Wechat:AppId" "你的AppId"
   dotnet user-secrets set "Wechat:AppSecret" "你的AppSecret"
   ```

3. 两台手机使用不同的微信号（都需要是项目成员）扫码预览，重复第 3 节的测试步骤。
4. 真机正式环境下，API 必须是 HTTPS、SignalR 必须是 WSS，并在公众平台配置 request 和 socket 合法域名；届时不再需要「打开调试」。
